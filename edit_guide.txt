정적 리뷰 기준으로 보면, 이번 버전은 이전의 dense head 방식에서 “structured text generation + object-slot retrieval” 방식으로 명확하게 재정의되어 있고, 큰 줄기의 로직은 꽤 잘 맞습니다. 현재 입력은 사실상 scene image + bbox가 포함된 prompt이고, visual_prompting: true일 때 scene 위에 head bbox를 직접 그린 뒤, Qwen3-VL-4B-Instruct에 "Point: x y\nObject: <obj_emb>" 형식의 답을 생성시키며, <obj_emb> 토큰 위치의 hidden state를 512차원으로 투영해 label embedding bank와 retrieval loss를 주는 구조입니다. 즉, 좌표는 텍스트 CE, 객체는 슬롯 hidden의 embedding retrieval로 학습됩니다. 이 설계 자체는 일관적입니다.

가장 좋은 점부터 말하면, 현재 버전은 loss 분해가 출력 포맷과 잘 맞습니다. processor_collate.py가 assistant target text에서 "Point:"의 두 숫자 span과 "Object: <obj_emb>"의 slot span을 문자 오프셋으로 찾고, 이를 token mask로 바꿔서 L_fmt, L_point, L_obj-ret를 분리합니다. loss_utils.py도 실제로 format token CE, point token CE, full-bank retrieval CE를 따로 계산해 가중합하고 있습니다. 또 test-time에는 beam search로 생성한 텍스트에서 point를 파싱하고, 생성된 <obj_emb> 슬롯이 있는 경우 한 번 더 re-encode해서 object embedding을 꺼내 retrieval top-k를 계산합니다. 구조적 출력과 loss/eval이 서로 엇갈리지는 않습니다.

다만 가장 중요한 논리 문제 두 개는 아직 남아 있습니다.

첫째, <obj_emb> 토큰 자체는 직접 LM loss로 학습되지 않습니다. 현재 fmt_mask = answer_mask & ~point_mask & ~object_mask라서 <obj_emb> 위치는 format CE에서 제외되고, object 쪽은 hidden state에 대한 retrieval CE만 받습니다. 게다가 config에서 loss_use_lm_fallback: false라서 Qwen이 내부적으로 계산하는 full LM loss도 실제 최적화에는 쓰지 않습니다. 결과적으로 학습 시 gold <obj_emb> 위치의 hidden은 학습되지만, 추론 시 모델이 <obj_emb> 토큰을 실제로 출력하도록 직접 압박하는 loss는 없습니다. test-time parse fail의 가장 가능성 높은 원인입니다. 이건 L_slot = masked_token_ce(logits, labels, object_mask)를 따로 추가하거나, 최소한 <obj_emb>를 fmt_mask에 포함시키는 방식으로 고치는 것이 좋습니다.

둘째, object label이 invalid인 샘플은 현재 point supervision까지 같이 잃습니다. datasets.py에서 target_text_valid와 target_object_valid가 모두 object-valid flag로 설정되고, build_train_inputs()는 이 target_valid를 component_masks()에 그대로 넘깁니다. 그런데 component_masks()는 target_valid[i] <= 0이면 그 샘플의 answer_mask, point_mask, object_mask를 전부 만들지 않고 건너뜁니다. 이후 target_point_valid=1.0이더라도 이미 point mask가 비어 있기 때문에 복구되지 않습니다. 즉, 객체 레이블이 없거나 매핑 실패한 샘플은 좌표 정답이 있어도 point loss를 못 받습니다. localization이 주목표라면 이건 상당히 아깝습니다. target_text_valid를 object validity와 분리해서 point/form supervision = 1, object supervision = object_valid로 나누는 쪽이 맞습니다.

속도/메모리 쪽에서는 지금도 불필요한 연산이 하나 크게 남아 있습니다. trainer는 train/val에서 항상 labels를 모델에 넘기고, model은 이를 그대로 self.qwen(**kwargs)에 전달합니다. 그래서 Qwen 내부의 full LM loss가 매 step 계산됩니다. 하지만 실제 최적화는 compute_structured_losses()의 mask 기반 CE와 retrieval loss를 쓰고, lm_loss는 loss_use_lm_fallback=false라서 fallback 상황이 아니면 버려집니다. 즉, 매 step마다 꽤 비싼 full LM loss를 계산하고도 사용하지 않는 상태입니다. 가장 큰 즉시 체감 최적화는, fallback을 끄는 현재 설정에서는 train/val forward에 labels를 넣지 않고 logits만 받아서 structured loss만 계산하게 바꾸는 것입니다. 이건 속도와 메모리를 동시에 줄일 수 있습니다.

그다음 불필요한 부분은 train/val collator에도 raw inputs를 항상 실어 나르는 점입니다. trainer는 train_collator, val_collator, test_collator를 모두 include_raw_inputs=True로 만들고, 코드 주석도 raw scene/text를 test-time re-encode용으로 항상 통과시킨다고 적고 있습니다. 하지만 그 raw passthrough는 실제로는 test의 pred_embeddings_from_generated()에서만 필요합니다. train/val에서는 scene_images, text_inputs를 안 써도 되므로, 지금은 CPU 메모리와 batch object 크기만 늘리고 있습니다. train/val만 include_raw_inputs=False, test만 True로 분리하는 편이 낫습니다.

평가 파이프라인은 논리적으로는 타당하지만, 비용이 큰 2-pass test입니다. 먼저 generate()로 top-1 beam 텍스트를 만든 뒤, 다시 pred_embeddings_from_generated()에서 scene image + user prompt + generated assistant text를 재인코딩해서 <obj_emb> 슬롯 hidden을 추출합니다. end-to-end 성능을 보려면 맞는 절차이지만, 개발 단계에서는 꽤 느립니다. 디버깅용으로는 num_beams=1로 낮추고, object retrieval이 목적이 아니면 이 두 번째 pass를 끄는 옵션을 두는 것이 좋습니다. 지금처럼 num_beams=3, max_new_tokens=16이면 test latency가 생각보다 큽니다.

작지만 실전적으로 중요한 점도 몇 개 있습니다. max_text_length는 config에 있지만, collator가 truncation=False를 강제로 쓰므로 현재는 사실상 dead setting입니다. prompt가 길어지면 이 값으로는 아무 것도 제한되지 않습니다. 또 현재 prompt는 출력 형식을 자세히 예시로 포함하고 있어서, 장점은 형식 안정성이지만 단점은 token 수가 늘고 placeholder 복사 경향이 생길 수 있다는 점입니다. 그리고 point_decimals=4는 normalized coordinate를 문자열로 생성하는 기준치로는 다소 촘촘합니다. 보통 2~3 decimals로 줄여도 위치 오차는 크게 나빠지지 않으면서 tokenization은 더 쉬워집니다.

긍정적으로 보이는 부분도 있습니다. best checkpoint를 test 전에 다시 로드하는 흐름은 살아 있고, gradient accumulation의 마지막 remainder window 스케일링도 이전보다 제대로 보정하도록 수정되어 있습니다. 또 trainer가 train/val label coverage와 test label map coverage를 시작 시점에 로그로 출력하고, test label embedding bank도 zero-row를 필터링한 뒤 valid row 수를 출력하도록 바뀌어 있어, 이전보다 data hygiene는 좋아졌습니다.

남은 아쉬움은 GazeFollow 기준 핵심 metric인 AUC가 현재 test metrics에 없습니다. run_test_metrics()와 print_test_metrics_table()는 Avg L2, Min L2, retrieval-based acc@1/3/multiacc@1만 반환합니다. 만약 이 모델을 기존 gaze estimation literature와 정면 비교하려면 AUC까지 넣는 것이 좋습니다. 지금 구조가 텍스트 생성형이더라도, point를 2D Gaussian heatmap으로 바꾸지 않더라도, evaluation utility에서 AUC는 별도로 계산할 수 있습니다.

정리하면, 지금 코드는 구성 자체는 꽤 설득력 있고, structured text + slot retrieval라는 디자인도 명확합니다. 다만 우선순위로 보면

<obj_emb> token LM supervision 추가,
invalid object label 샘플에서도 point supervision이 살아 있게 mask logic 분리,
fallback off일 때 Qwen 내부 full LM loss 계산 제거,
train/val raw input passthrough 제거,
이 네 가지를 먼저 고치는 것이 가장 중요합니다.
이 네 개가 정리되면, 로직상 가장 큰 구멍과 가장 큰 비효율이 동시에 없어집니다.
