[ 개요 ]
--------
SemGaze는 전용 CNN/Transformer 디코더 기반으로 gaze localization과 object
recognition을 수행한다. QWEN_GazeEstimation은 동일한 두 task를 Qwen3-VL-4B
(VLM)의 텍스트 생성 방식으로 대체한 구현이다.

두 구현 간의 근본적인 아키텍처 차이(heatmap 디코더 vs LM 텍스트 생성)는
의도된 설계 선택이므로, 이 보고서에서는 구현 상의 실제 오류나 의미론적
불일치에 초점을 맞춘다.


================================================================================
1. LOCALIZATION (Gaze Point 예측)
================================================================================

[ SemGaze ]
- 출력: 64×64 heatmap → spatial_argmax2d() 또는 DARK decoding (Taylor 2차 근사,
  sub-pixel 정확도)
- 손실: MSE heatmap loss + angular loss (head→gaze 방향 벡터 기반)

[ QWEN_GazeEstimation ]
- 출력: 텍스트 "Point: x y" 생성 → 정규표현식으로 파싱
- 손실: L_point = LM CE (x y 좌표 토큰 위치에 대한 다음 토큰 예측 손실)

[ 평가 지표 비교 ]

  SemGaze                          QWEN_GazeEstimation
  ─────────────────────────────    ────────────────────────────────
  dist_to_avg   (avg → pred L2)   (없음)  ← 미구현
  avg_dist      (각 annotator별   Avg L2  ← 동일
                 평균 L2)
  min_dist      (최솟값 L2)       Min L2  ← 동일

[ 문제점 ]
  - SemGaze에서 표준적으로 보고하는 dist_to_avg (예측 좌표와 모든 annotator
    GT 좌표의 평균점 사이 L2 거리)가 QWEN 구현에 없다.
  - GazeFollow 논문들에서 avg_dist(= Avg L2), min_dist(= Min L2), 그리고
    dist_to_avg가 함께 보고되는 것이 일반적이다.
  - 해결 방법: run_test_metrics 내에서 gt_points의 평균 좌표를 구한 뒤
    예측값과의 L2를 추가로 계산하면 된다. (간단한 추가 사항)

  그 외 구현 자체의 논리적 오류는 없다.


================================================================================
2. RECOGNITION (Object 예측)
================================================================================

[ SemGaze - 훈련 손실: In-batch InfoNCE ]
  - GT 임베딩 중 unique한 것만 추려서 key set으로 사용
  - logits = pred_emb @ unique_gt_emb.T * logit_scale.exp()
  - logit_scale: 학습 가능한 온도 파라미터 (CLIP 방식)
  - 배치 내 유니크 GT만 negative로 사용 → 배치 크기에 따라 negative 수 변동

[ QWEN_GazeEstimation - 훈련 손실: Full-bank InfoNCE ]
  - 전체 라벨 임베딩 뱅크 (346개)를 key set으로 사용
  - logits = pred_emb @ full_bank.T / temperature (고정값 0.07)
  - 모든 배치에서 동일한 negative 집합 → 더 안정적인 학습

  → 두 방식 모두 유효한 InfoNCE 변형이다. QWEN의 full-bank 방식은 SemGaze의
    in-batch 방식에 비해 negative 집합이 일관되어 오히려 학습 안정성이 높다.
    구현 상의 문제 없음.

[ 추론 시 Top-k 검색 ]

  SemGaze:
    gaze_label_logit = pred_emb @ vocab_emb.T  # 온도 미적용
    topk = logit.topk(k)

  QWEN:
    sim = (q @ bank.T) / temperature  # 온도 적용 후 topk
    topk = sim.topk(k)

  → topk()는 대소 관계만 보므로 온도 나누기는 ranking에 영향 없다.
    결과적으로 동일한 순위 도출. 문제 없음.

[ 임베딩 추출 방식 ]

  SemGaze:
    GazeDecoder의 two-way transformer 출력 gaze token
    → label_mlp (768→512, 6-layer FC + ReLU) → L2 normalize

  QWEN:
    LM의 <obj_emb> 토큰 위치 hidden state (R^2560)
    → linear projector (2560→512) → L2 normalize

  → 아키텍처적 차이이며 구현 상 문제 없음.


================================================================================
3. 평가 지표 (Acc@1, Acc@3, MultiAcc@1)
================================================================================

[ SemGaze ]

  Acc@1, Acc@3:
    torchmetrics.Accuracy(task="multiclass", num_classes=vocab_size, top_k=1 or 3)
    → 단일 GT label_id 대비 top-k 예측 정확도

  MultiAcc@1:
    MultiAccuracy 클래스: top-1 예측이 다중 annotator GT 레이블 중 하나라도
    일치하면 정답으로 처리 (padding -1 무시)

[ QWEN_GazeEstimation (이번 수정 이후) ]

  Acc@1, Acc@3:
    gt_primary_set (단일 canonical GT 레이블) 대비 top-k 비교
    → SemGaze의 단일 GT 기준 acc@1/3과 의미론적으로 동일

  MultiAcc@1:
    gt_multi_set (gaze_gt_labels 열의 모든 valid GT) 대비 top-1 비교
    → SemGaze의 MultiAcc@1과 의미론적으로 동일

  ※ 이번 수정 이전의 구현 문제:
    - gt_set이 primary GT와 multi GT를 모두 합쳐서 acc@1/acc@3/multiacc@1
      세 지표 모두에 동일하게 사용됨 → acc@1과 multiacc@1이 항상 동일한 값
    - 이번 수정에서 gt_primary_set / gt_multi_set으로 분리하여 수정 완료.


================================================================================
4. 손실 구조 전반 비교
================================================================================

  SemGaze                   가중치     QWEN_GazeEstimation        가중치
  ────────────────────────  ──────     ─────────────────────────  ──────
  Heatmap MSE               설정값     (없음 — 텍스트 생성 방식)
  Angular loss              설정값     (없음)
  InfoNCE (in-batch)        설정값     InfoNCE (full-bank)        0.5
                                       L_point (LM CE, x y)       2.0
                                       L_fmt   (LM CE, 포맷토큰)  0.6

  QWEN에는 heatmap/angular 손실이 없는 것은 의도된 설계 (텍스트 생성으로 대체).
  L_point + L_fmt 구조는 좌표 예측과 포맷 안정화를 분리한 합리적 설계.

  ※ L_fmt 구현 관련 (이번 수정 전 문제):
    - 기존 loss_mask_answer가 answer 전체(포맷+좌표+<obj_emb>) 토큰을 커버
    - L_point와 L_fmt이 좌표 토큰에서 중복 계산됨
    - 이번 수정에서 fmt_mask = answer_mask & ~point_mask & ~object_mask로
      분리하여, L_fmt은 "Point: "와 "\nObject: " 포맷 토큰만 커버하도록 수정.

5. 기타 구현 일관성 검토
================================================================================

[5-1] <obj_emb> 토큰 hidden state 추출 (teacher forcing 하에서)
  - 훈련 시 joint_inputs에는 prompt + answer(<obj_emb> 포함) 전체가 있음
  - loss_mask_object가 <obj_emb> 토큰 위치를 정확히 식별하며, 이것이
    object_slot_mask로 모델에 전달됨
  - 모델은 해당 위치의 last_hidden_state를 pooling하여 projector 통과
  - Causal LM의 특성상 <obj_emb> 위치의 hidden state는 해당 토큰까지의
    전체 컨텍스트를 반영함 → 구현 정확함

[5-2] 추론 시 임베딩 추출 (pred_embeddings_from_generated)
  - 모델이 <obj_emb>를 생성하면 → 생성 텍스트를 다시 인코딩
  - <obj_emb>는 special token으로 등록되어 skip_special_tokens=False로
    디코딩 시 보존됨 (Qwen의 <|...|> 패턴과 달리 정규식으로 제거되지 않음)
  - 재인코딩 후 component_masks로 <obj_emb> 위치 찾아 hidden state 추출
  - 구현 정확함

[5-3] 데이터 증강
  SemGaze:  RandomCropSafeGaze (p=0.8), RandomHFlip (p=0.5), ColorJitter (p=0.8)
  QWEN:     safe_crop (p=0.5), maybe_hflip (p=0.5), color_jitter (p=0.8)
  → 동일한 증강 전략. QWEN의 crop 확률이 0.5로 SemGaze(0.8)보다 낮은 것은
    설계 선택이며 문제는 아님.

[5-4] 임베딩 뱅크 정규화
  SemGaze:  vocab_emb = F.normalize(torch.stack(vocab_emb), dim=1)
  QWEN:     build_vocab_embedding_matrix() 내 normalize=True → F.normalize 적용
  → 둘 다 L2 정규화 적용. 동일.

[5-5] 체크포인트 저장/로드
  - LoRA adapter, processor, object_projector를 각각 저장
  - load_checkpoint_for_eval에서 load_adapter → set_adapter로 로드
  - 구현 정확함


================================================================================
6. 요약: 발견된 문제점
================================================================================

[ 수정이 필요했던 문제 (이번 수정에서 해결) ]

  ① multiacc@1 ≡ acc@1 버그
     gt_set이 단일/다중 GT를 모두 포함하여 acc@1과 multiacc@1이 동일했음.
     → gt_primary_set / gt_multi_set 분리로 수정 완료.

  ② L_fmt 마스크 중복
     loss_mask_answer가 좌표 토큰과 <obj_emb>까지 포함하여 L_point와 중복.
     → fmt_mask = answer_mask & ~point_mask & ~object_mask로 수정 완료.

[ 미구현이지만 중요한 사항 ]

  ③ dist_to_avg 지표 미구현
     GazeFollow 논문들의 표준 평가 지표 중 하나. 추가 권장.
     구현: gt_points의 평균 좌표 vs 예측 좌표 L2 거리.

[ 아키텍처 차이 (의도된 설계) ]

  - SemGaze의 heatmap 기반 localization vs QWEN의 텍스트 토큰 기반 localization
  - SemGaze의 in-batch InfoNCE vs QWEN의 full-bank InfoNCE
  - SemGaze의 다중 손실(heatmap+angular+InfoNCE) vs QWEN의 (L_fmt+L_point+L_obj-ret)
  → 모두 의도된 차이이며 구현 오류 아님.

================================================================================
결론: QWEN_GazeEstimation의 핵심 구현 로직은 SemGaze의 평가 프로토콜과
의미론적으로 일치하도록 구현되어 있으며, 이번 수정(multiacc@1, L_fmt 분리)
이후 잔여 구조적 문제는 없다. dist_to_avg 지표 추가만 남은 권장 사항이다.
